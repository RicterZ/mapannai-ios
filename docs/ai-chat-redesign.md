# AI 对话重设计：全屏旅途工作区

状态：视觉方向已确认，第一阶段全屏文字UI已实现，交互验证进行中；客户端MCP、结构化控件及结果卡仍为提案。

## 目标与第一阶段边界

彻底替换现有半屏气泡聊天，参考圆周旅迹的全屏阅读、轻量输入、可理解的工具过程与对话历史组织方式，保留 MapAnNai 的卡片档案语言。

第一阶段以文字对话完成需求澄清和行程讨论：全屏呈现、文本与 Markdown、流式响应、工具过程折叠、历史会话、停止与错误恢复。沿用现有 `/api/ai/chat` NDJSON，不增加未经约定的接口。

日期选择、多选问卷、结构化行程卡及客户端 MCP 操作属于后续阶段，不能仅凭模型文字生成可执行控件。现有服务端工具可能修改行程，第一阶段并不等于服务端只读；展示已保存结论必须有真实工具结果支持。

## 页面结构

### 全屏容器与导航

- iPhone 从首页输入、最近会话、会话记录进入同一个全屏聊天工作区，不再使用 medium/large 聊天 sheet，不露出地图。
- iPad 同样采用全屏工作区，正文居中，最大宽度建议720pt；历史侧栏留到后续，不强行沿用右侧地图聊天区。
- 左侧44pt返回命中，无背景系统 `chevron.left`，支持左边缘右滑返回；中间会话标题单行截断；右侧44pt无背景 `bubble.left` 16pt常规线重图标打开会话列表。左右等宽，标题严格居中。
- 新会话标题为“聊聊下一程”，有对话后沿用现有会话标题；不擅自改为模型生成标题。
- 返回保留会话与正在进行的回复，仅隐藏工作区；显式停止或连接切换才取消请求，返回进入前的首页/地图和原滚动位置。关闭不会删除服务端已完成写入。
- 首页提交时新建会话；历史/最近会话进入已有会话，不自动发送消息。API配置仍只在应用设置。
- 全屏展开/关闭使用平台过渡，不重做首页抽卡动画，不把聊天页作为一张旅途卡参与抽卡。

### 消息画布

- 白色底，正文系统label；助手回答不加大灰色气泡，不显示重复头像/角色标签。
- 用户消息右对齐，浅中性填色小圆角气泡，最大宽度约80%，正文17pt；不再用饱和蓝底白字。
- 助手正文17pt，段落间距12pt，行距约5pt；横向20pt留白。标题、列表、粗体和链接按统一Markdown样式呈现，不通过不同HTML模板重复渲染。
- 消息轮次间距24–28pt；单条助手正文可用满正文宽度，连续助手片段保持顺序，工具消息不作为正文气泡显示。
- 不添加巨大空欢迎卡。新会话显示一句“从一个目的地，或一个想法开始。”，底部输入可直接聚焦；不开空请求。
- 完成回复后允许复制整条回答；流式阶段不闪动复制按钮、不追加每段复制入口。
- 未建立可靠数据绑定之前，模型写的“已创建行程”只是文本，不自动生成按钮或跳转。

### 输入区与键盘

- `safeAreaInset` 预留输入区，水平16pt、垂直12pt；白色输入框，22pt圆角，轻描边或regularMaterial，不铺整块硬白底。
- 多行文本1–5行，最小输入区56–60pt；只有输入与右侧动作，没有不工作的加号、话筒、功能胶囊。
- 待发送用无背景 `paperplane` 图标、44pt命中；空文本/未配置/未就绪禁用。回复中同位置替换为停止图标，保持尺寸和位置。
- iPhone多行输入保留换行，点击图标发送；外接键盘Command+Return发送，避免中文输入法选词时误发。首页单行仍可回车发送。
- 点击正文空白和拖动收键盘；输入框内点选/选中文字不能导致失焦，不加此前被否定的键盘收起工具栏。
- 键盘出现时只保证输入区可见，不将整段对话滚动到中间。背景延伸到键盘圆角后方，不出现白色侧翼或多余padding。
- 内容可在输入区材质后滚动，边缘轻淡化但不遮住最后一行。减少动态效果时不额外插值。

### 滚动行为

- 打开/切换会话默认最新消息；用户处于底部附近时跟随流式增长。
- 用户主动上滚后暂停自动跟随；不能每个token/每次尺寸变化都强制滚到底部。现有代码的无条件`scrollTo`需要替换。
- 离底部超过约80pt时显示轻量 `arrow.down` 跳到最新按钮，位于输入上方右侧，不挡正文；点击后恢复跟随。
- 键盘展开只对输入区做遮挡避让，不取消用户阅读历史的意图。

## 工具过程与错误

同一轮回答用一个过程块：“正在处理行程…”；只有已知工具时才显示“正在搜索地点”等具体状态。默认收起，点击 `chevron.down/up` 展开。

展开区以caption/footnote显示已知工具名、运行/完成/失败结果；不显示API Key、token、原始请求体、完整模型上下文或预签名URL。不将未知工具标记为成功，不显示虚构百分比。

现有事件只有`status.name`与持久化`assistant.tool_calls`/`tool.tool_call_id`等证据。工具完成状态可由匹配的tool消息确认；没有call ID的status仅能表达当前概况，不能可靠区分同名并发实例。没有时间戳、耗时和来源链接就不编造这些字段。

网络中断保留部分回答和已知工具结果，显示紧凑内联错误：“回复中断，部分操作可能已保存。”提供继续输入，不自动重试带写入能力的请求。停止并不回滚已经执行的服务端写入。

服务切换取消旧流，generation隔离过期事件；本地会话读取失败保留原文件，清空必须确认。配置无效时显示前往设置，不假装正在思考。

## 会话列表

- 全屏聊天右侧菜单及首页会话入口复用同一列表组件，默认原生半屏/全屏sheet；这是辅助选择器，不是聊天的半屏容器。
- 标题“对话”，右侧新建，当前行用低对比描边/勾选强调，其他行使用中性背景，不能和旅途卡片3D效果混淆。
- 行只显示实际保存的标题；现有记录没有更新时间、封面和关联旅行，不显示“2天前”等虚构信息。后续新增字段须兼容旧本地记录。
- 新建、切换、删除在busy时禁用，或先明确停止再操作；不把流中切换的结果挂到另一段会话。
- 删除仅删除本地会话，不删除旅途；确认文案明确这一点。关闭列表不改变当前对话。

## 客户端控件 / MCP 的能力边界

客户端控件操作不是任意模拟点击。设计为有类型、可授权的业务动作，iOS与Web各自适配同一语义，模型不能调用任意selector、执行JavaScript或访问任意文件。

以下是候选能力，不是已存在的MCP工具名或接口：

| 能力类别 | 示例语义 | 约束 |
| --- | --- | --- |
| 读取可见上下文 | 当前旅行/日期/选中地点、已打开页面 | 只返回用户允许的最小上下文，不含凭据 |
| 导航与展示 | 打开已有旅行/日期、预览地点、聚焦地图 | 校验真实ID、权限与当前连接；不写业务数据 |
| 填写草稿 | 打开现有编辑器并预填标题/日期 | 不自动保存，不覆盖用户未提交草稿 |
| 请求交互 | 日期范围、多选偏好 | 展示结构化控件，结果明确回传，允许取消 |
| 修改业务数据 | 保存地点/行程、移除成员 | 复用既有API和事务规则；敏感操作确认，不从文字解析执行 |

服务器负责搜索、计划和业务工具；客户端负责界面导航、展示、草稿及本地交互。两者不得重复执行同一次写入。客户端操作必须收到正式合约事件才执行，不能把服务端`status`当作执行指令。

未来合约至少需要：能力协商/版本、request ID、关联会话/轮次、工具名与严格参数schema、作用域、有效期、取消、确认、结果/错误、幂等与连接隔离。结果回传通道、断线恢复、跨端路由尚未约定；不假设现有单向NDJSON已支持双向MCP。

同一会话只交给当前活跃客户端执行；iOS/Web不能同时响应并重复保存。应用关闭或用户接管导航后，旧操作不得在后台突然弹页面。历史回放仅展示，不重新执行。

## 分阶段交付

1. 视觉确认：全屏新会话、正文/工具处理中、键盘展开、会话列表、错误/停止五组设计稿。使用真实控件尺寸，不只提供概念描述。
2. 第一阶段实现：重做`AIPlannerView`的消息、输入和滚动；统一首页/地图进入与退出；抽出共享会话列表；继续复用`AIPlannerStore`、存储、流式协议。删除旧半屏聊天呈现及重复历史入口，不新建第二套网络逻辑。
3. 测试与安装：mock只读流验证状态；0/1/3首页进入、历史续聊、键盘、滚动、停止、配置、失败、连接切换回归；发模拟器截图并安装真机。
4. 合约设计：和服务端/Web确认客户端能力协议及授权方式，再设计日期/偏好交互与结果卡片。没有正式合约不实现“客户端MCP”。
5. 第二阶段：先接导航/预览/草稿等低风险能力，再接需确认的写入和结构化计划展示。

## 第一阶段验收

- 所有聊天入口真正全屏，关闭恢复原页；iPad布局也没有半屏地图残留。
- 正文无大灰气泡，用户消息轻量右对齐，状态与回复不争主次；200字/2000字、长标题与大字均不裁切。
- 流式回复底部跟随，上滚可阅读历史，跳到最新可恢复；完成替换不闪白、不跳位置。
- 键盘不遮输入，点空白/拖动可收起；无额外收起图标，圆角周围背景一致。
- 工具块可折叠，未知状态不伪称完成，敏感原始信息不泄漏。
- 会话切换不串流；关闭/停止不自动重试写入，不回放客户端动作。
- 未配置、离线、服务不支持AI、本地存储失败都有明确可操作反馈。
- 真机录屏与逐帧检查输入/关闭交接；没有真机/Instruments证据不宣称动画流畅度已验证。
